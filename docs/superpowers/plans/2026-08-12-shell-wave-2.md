# Shell Overhaul Wave 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The four library screens — Applications list, Application detail, Capability Map, Solutions — rebuilt on the Wave-1 screen system, plus the ledgered fast-follows, verified by the screenshot matrix and deployed.

**Architecture:** Same machinery as Wave 1: every screen adopts `page_shell`/`empty_state`/`stat_card`/`section_card` from `app/templates/macros/page_shell.html` (read its header comment: page_shell/stat_card are expression-called, section_card is block-called). Wave-1 invariants are binding and gate-enforced: sidebar-links ≤25, design-tokens 0, fabricated-data 0, a11y burns down on rebuilt pages.

**Tech Stack:** Flask/Jinja2, Tailwind v3 (`scripts/build_css.py`, CLI in `scripts/bin/`), Alpine.js, pytest, `scripts/screenshot_matrix.py`.

**Spec:** `docs/superpowers/specs/2026-08-12-shell-overhaul-design.md` — Principles binding. Wave-1 ledger context: `.superpowers/sdd/2026-08-12-shell-wave-1/progress.md`.

## Global Constraints

Identical to Wave 1's (docs/superpowers/plans/2026-08-12-shell-wave-1.md Global Constraints — read them; they bind every task here verbatim), plus:
- Rebuilt screens must keep their existing data-trust strengths intact: the Applications data-quality banner, the Application-detail completeness banner and "No ownership data → Add via Edit" pattern, capability coverage honesty. Regressing an honesty feature is a Critical finding.
- Every rebuilt screen gets added to `scripts/screenshot_matrix.py`'s route list in the same task that rebuilds it.
- Nothing clips at 1024 — structure for it (no fixed widths; `overflow-x-auto` on wide tables).
