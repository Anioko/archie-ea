### Task 1: tenant-scoping verify gate (the headline)

**Files:**
- Create: `scripts/check_tenant_scoping.py`
- Modify: `scripts/verify.py` (register gate `tenant-scoping`, tag `static`), `verification_baseline.json` (add `"tenant_scoping": <measured>` under ratchets)
- Test: `tests/test_tenant_scoping_gate.py`

**Interfaces:** `python scripts/check_tenant_scoping.py --count` prints the integer count of violations; `--json` prints `{"count": N, "violations": [{"file","line","model","reason"}]}`; exit 1 if count > baseline.

**What it flags (the cross-tenant class, six instances so far):** a request-path query/aggregate over a model that is NOT `TenantMixin` and HAS an `organization_id` column, with no `organization_id` filter in the same statement. Detection approach (AST over `app/**/*.py`, pragmatic not perfect):
- Identify model classes that declare `organization_id = db.Column(...)` but do NOT inherit `TenantMixin` (parse `app/models/**`). Call this set `LEAKY_MODELS` (e.g. `ApplicationCapabilityMapping`, `User`, `ComplianceViolation`, and the ea/workflow instance models the P0 wave touched).
- Flag any `.query`/`db.session.query(<LeakyModel>...)`/`func.count(<LeakyModel>...)`/`<LeakyModel>.query` expression in `app/modules/**`, `app/api/**`, `app/main/**`, `app/routes/**`, `app/services/**` where the enclosing statement/chain has no `.filter(...organization_id...)` / `filter_by(organization_id=...)` and no `g.current_org_id` reference within N lines.
- Also flag a `@cached()` decorator on a route whose `key_func` does not reference `g.current_org_id`/org (the 6th-instance cache-key class) — OR scope that to a simpler heuristic: `@cached(` without `key_func=` on a function in the route dirs.
- Per-line escape hatch `tenant-scoping-ok: <reason>` (like the repo's other hatches) for genuine exceptions (CLI/scheduler paths, aggregates that are intentionally global).

**Approach note:** perfection is not the bar — the existing ratchets are heuristic too. Aim to catch the six known instances' SHAPE. Verify the gate FLAGS a deliberately-reintroduced unfiltered query and PASSES the current (fixed) tree. Set the baseline to whatever the current tree measures (the known instances are fixed, so ideally low; if pre-existing unfixed instances remain, baseline at that count and list them).

- [ ] **Step 1: Failing test** — `tests/test_tenant_scoping_gate.py`: feed the checker a tiny fixture module with (a) a LEAKY_MODEL `.query.count()` with no org filter → asserts it's flagged; (b) the same with `.filter_by(organization_id=...)` → asserts NOT flagged; (c) a `tenant-scoping-ok:` line → asserts NOT flagged; (d) a TenantMixin model queried bare → asserts NOT flagged (auto-filtered).
- [ ] **Step 2: Verify fail.**
- [ ] **Step 3: Implement** the checker + registration + baseline. Read `scripts/check_raw_sql_tenancy.py` and mirror its structure/registration exactly. Run it on the real tree; record the count and the violation list in your report.
- [ ] **Step 4: All green** — `pytest tests/test_tenant_scoping_gate.py -q`; `python scripts/check_tenant_scoping.py --count`; `python scripts/verify.py --gate tenant-scoping`.
- [ ] **Step 5: Commit** `feat(verify): tenant-scoping gate — the cross-tenant class cannot recur`.
